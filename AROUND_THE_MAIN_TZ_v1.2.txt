
31. MOBILE EDITION — PAGE LAYOUT STANDARD

Mobile Edition является постраничным представлением одного Edition.

PAGE 01:
- использует единый branded header image:
  assets/mobile-header.png;
- отдельный logo.png в верхней части страницы НЕ используется;
- header содержит фирменную визуальную идентичность AROUND THE MAIN;
- после header отображаются:
  EDITION XXXX;
  publication date;
  edition name;
  PAGE 01;
- после информационного блока начинается контент выпуска;
- в нижней части страницы располагается единый DAILY BRIEF footer.

PAGES 02+:
- branded header image НЕ используется;
- отдельный logo НЕ используется;
- в верхней части располагается компактная строка:
  edition name слева;
  PAGE XX справа;
- под строкой располагается горизонтальный divider;
- далее располагается контент страницы;
- в нижней части каждой страницы располагается тот же DAILY BRIEF footer.

PAGE NUMBER:
- номер страницы формируется динамически;
- формат:
  PAGE 01
  PAGE 02
  PAGE 03
  ...
- номер страницы не должен быть задан глобальной переменной;
- каждая страница должна получать собственный page_number.

EDITION NAME:
Название выпуска определяется типом/временем Edition.

Допустимые названия:
- Morning Briefing
- Midday Update
- Evening Round-up

Название должно автоматически использоваться на всех страницах соответствующего выпуска.

FOOTER:
- footer должен быть единообразным на всех страницах Mobile Edition;
- footer располагается в нижней части страницы;
- содержит DAILY BRIEF;
- содержит краткое описание;
- содержит GLOBAL NEWS • AROUND THE MAIN;
- содержит Telegram @aroundthemain;
- содержит X @aroundthemain;
- нижняя фирменная полоса содержит:
  STAY INFORMED. STAY AHEAD.

VISUAL STYLE:
- единый газетный cream/paper background на всех страницах;
- основной цвет текста — black;
- фирменный акцент — red;
- header image сохраняет исходные пропорции;
- дизайн всех страниц должен восприниматься как один физический/цифровой выпуск;
- не допускается изменение структуры или цветовой схемы между страницами одного выпуска без редакционной необходимости.

32. LATEST APPROVED MOBILE EDITION REFINEMENTS — 17 SEPTEMBER 2026

Эти требования являются утверждённым следующим этапом до начала соответствующих изменений в renderer и production pipeline.

32.1 EVENT CARD SECTION / GEOGRAPHY LABELS
- не использовать WORLD как автоматическую метку для всех карточек;
- сначала использовать конкретную географию из metadata события, если она достаточно определена;
- при наличии нескольких значимых территорий допускается компактная комбинация, например:
  RUSSIA / UKRAINE;
- для событий регионального масштаба использовать соответствующий регион, например EUROPE;
- если конкретная география отсутствует или не является полезной для читателя, использовать тематическую editorial category;
- WORLD использовать только как настоящий fallback;
- label должен отражать содержание события, а не просто значение поля content.section.

32.2 MARKETS TODAY — APPROVED LAYOUT
MARKETS TODAY должен быть компактным, читаемым и визуально связанным с footer.

Структура:

MARKETS TODAY
INDEXES       S&P 500 ... | DOW ...
COMMODITIES  BRENT ... | GOLD ... | WTI ...
CURRENCY / GLOBAL  EUR/USD ... | USD/CNY ... | DXY ...

Требования:
- показатели разделяются на три смысловые категории;
- каждая категория располагается на отдельной строке;
- не объединять все показатели в одну длинную строку;
- не использовать три крупные вертикальные колонки как основной вариант;
- шрифт показателей должен быть немного крупнее текущего мелкого варианта, чтобы блок оставался читаемым в Telegram preview;
- между тремя строками должен быть небольшой, но отчётливый вертикальный зазор;
- значения и проценты изменений должны использовать фактические поля market snapshot, включая change_pct;
- renderer не должен самостоятельно получать новые котировки;
- используется immutable market snapshot конкретного Edition;
- блок MARKETS TODAY должен быть прижат к верхней границе footer с небольшим визуально корректным зазором;
- нижняя граница market block должна быть определена геометрией footer, чтобы market block никогда не пересекался с footer;
- после фиксации высоты market block свободное пространство над ним должно использоваться Layout Engine для размещения дополнительной новости;
- на PAGE 01 разрешается размещать 4 news blocks вместо 3, если их содержимое помещается без ухудшения читаемости;
- четыре карточки не должны приводить к чрезмерному уменьшению headline, summary или source text;
- если четыре карточки не помещаются с установленными минимальными размерами, Layout Engine должен сохранить 3 карточки и не ломать страницу.

32.3 PAGE 01 VERTICAL BUDGET
- PAGE 01 должна рассчитывать доступную высоту контента от фактической позиции header и footer;
- MARKETS TODAY является нижним фиксированным информационным блоком непосредственно перед footer;
- news area использует всё оставшееся безопасное пространство между header/content start и MARKETS TODAY;
- расстояние между последней news card и MARKETS TODAY должно быть небольшим и стабильным;
- запрещены большие пустые вертикальные области перед MARKETS TODAY;
- Layout Engine должен стремиться к 4 news blocks на PAGE 01, когда минимальные размеры карточек и readability constraints позволяют это.

32.4 LAST PAGE READABILITY
- страницы с несколькими news cards должны сохранять читаемость в обычном Telegram preview настолько, насколько это возможно при фиксированном размере изображения;
- не уменьшать страницу или текст только ради искусственного увеличения количества карточек;
- приоритет: readable text → complete cards → balanced page → maximum useful content;
- если page content превышает безопасную высоту, переносить материал на следующую страницу, а не сжимать текст до нечитаемого размера.

32.5 PUBLICATION TIMING NOTICE
Если на последней странице остаётся достаточно свободного места для дополнительного editorial/brand block, допускается показывать короткое уведомление:

"Publication timing may vary. Some editions may be delayed while we take additional time to check sources, facts and context before publication."

Требования:
- уведомление не должно занимать место у новостных карточек, если оно ухудшает читаемость;
- оно должно появляться только при наличии безопасного свободного места;
- формулировка должна объяснять возможные задержки без обещания абсолютной безошибочности или полной проверки каждого факта;
- уведомление не является новостной карточкой и не должно влиять на editorial ranking.

32.6 EDITORIAL FRESHNESS / COUNTRY COVERAGE QC
Перед production publication Quality Control должен проверять:
- актуальность материала относительно Editorial Snapshot;
- дату и время публикации источника;
- наличие более свежего существенного развития, если событие продолжается;
- географическую корректность metadata;
- соответствие headline и summary фактическому содержанию источника;
- источник и уровень verification;
- отсутствие очевидных duplicate stories;
- корректность market snapshot и его freshness metadata;
- отсутствие устаревших market values;
- баланс международного покрытия без искусственного заполнения страниц.

32.7 PARTNER / PROMOTIONAL CONTENT
- partner, sponsored или явно promotional content не должен автоматически публиковаться как обычная независимая news story;
- такие материалы должны быть распознаны и обработаны отдельным editorial rule;
- наличие partner/promotional статуса должно быть учтено до финального editorial selection;
- editorial system не должна маскировать рекламный материал под независимое новостное сообщение.

32.8 VISUAL CONTENT POLICY
- news/editorial photographs и AI-generated news illustrations не используются как обязательная часть текущей Mobile Edition;
- допускаются только необходимые branding graphics и элементы фирменного оформления;
- отсутствие фотографии не должно считаться дефектом карточки;
- текущий Mobile Edition остаётся text-first newspaper-style format.

32.9 SCHEDULER RELIABILITY
- требуемое расписание сохраняется:
  America/New_York
  07:00
  13:00
  20:00
- watchdog должен обрабатывать пропущенные или задержанные slots после фактического запуска workflow;
- задержка запуска GitHub Actions не должна приводить к потере edition;
- для будущей production-hardening стадии рассмотреть внешний scheduler/trigger, если требуется более точное соответствие clock time;
- scheduler reliability не должна смешиваться с editorial snapshot time: время фактической обработки и время целевого выпуска должны храниться отдельно.

32.10 IMPLEMENTATION ORDER
1. Fix event card geography/category labels.
2. Implement approved three-line MARKETS TODAY block.
3. Increase market text size while preserving fit.
4. Anchor MARKETS TODAY immediately above footer with a controlled gap.
5. Recalculate PAGE 01 vertical budget around the fixed market/footer area.
6. Enable 4 news cards on PAGE 01 when minimum readability constraints permit.
7. Add conditional publication timing notice to the last page.
8. Add/strengthen editorial freshness, geography and promotional-content QC.
9. Run renderer tests and full regression.
10. Render a complete real-edition preview and inspect all pages before production merge.

32.11 NON-NEGOTIABLE PRINCIPLE
Не оптимизировать количество карточек за счёт читаемости.

Priority order:

READABILITY
→ EDITORIAL ACCURACY
→ SOURCE CLARITY
→ PAGE BALANCE
→ MAXIMUM USEFUL CONTENT

ONE EDITION → CLEAR INFORMATION → CONTROLLED LAYOUT → RELIABLE PUBLICATION
